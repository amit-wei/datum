# The stance: what to tell every step, and how to write it (2026-10-18)

Condensed from three Sonnet research agents' reports (#16), run in parallel with no
checker. VERIFIED means the agent read the primary source's relevant text;
VERIFIED-secondary means only a summary or secondary source; INFERRED means reasoning.
Paywalled standards (DO-178C, ARP4754A, IEC 62304, INCOSE) were not read and appear
only as VERIFIED-secondary. The evidence backs the practices, not the effect of any
wording on an agent: that needs a test (P12 and the packaging rig).

**Questions:**
1. Which systems engineering practices prevent the costliest errors? Weighted toward
   SE on software.
2. Which software practices carry over to AI implementers?
3. How should instructions in a skill be written so an agent follows them over a long
   task? Triggering and descriptions are excluded (see `2026-10-18-skill-descriptions.md`).

Each answer could be a rule, a guideline, an approach or a way of thinking. Each says
where it belongs: the stance (holds at every step), a step's end condition, a reviewer
check, or a technique.

## Where the three agree

- **"Think as a systems engineer, from first principles" names no behaviour.** All
  three say so.
  - Persona lines shift tone and focus but show no gain in accuracy (Zheng et al.,
    162 roles; Wharton 2025, which a 2026 preprint disputes). VERIFIED-secondary. Both
    test one-shot factual questions, not agent procedure.
  - "First principles" alone can invite re-deriving what is settled. INFERRED.
  - The operational form: start from the need and the givens, and derive rather than
    recall the usual solution. Pattern completion from training data is the failure it
    counters. INFERRED.
- **The "done" line is right in aim but is a definition, not a procedure.** That
  matches lesson 7. #15 is a different failure from the one the line forbids: the
  agent did check the model, and the model lacked a child. The fix is to judge
  completeness from what something must cover, not from what exists:
  - SEH: every top-level requirement allocated to the lower level; a requirement with
    no parent is a flawed trace or gold plating. VERIFIED (NASA SP-2016-6105, 6.2).
  - Ariane 501: the failing case was never specified because the spec lacked the
    trajectory data. VERIFIED-secondary.
  - MCO: V&V did not adequately cover the ground software, which is what failed.
    VERIFIED (MIB Phase I).
- **Keep the stance short.** Every step includes it, so it costs context everywhere.
  - Context files tended to lower agent success and raised cost by more than 20%.
    VERIFIED-secondary (AGENTS.md study).
  - Bloated CLAUDE.md files cause instructions to be ignored. VERIFIED (Claude Code
    docs).
  - Aim: under about 10 lines. Interface control, information hiding, design by
    contract, deep modules, and Conway's, Hyrum's and Gall's laws go to techniques and
    reviewer checks.

**What changes from hardware to software:**
- **Cost multipliers do not transfer as numbers.** Stecklein's operations factor comes
  from an unserviceable satellite, and the software data is from 1981. VERIFIED. Cite
  the shape, not a multiplier: decisions commit cost, and errors cascade across
  interfaces.
- **No wear-out.** Every software fault is a design fault, so identical copies fail
  identically.
- **Interfaces are invisible**: units, encodings, ordering, timing, error semantics.
- **Reuse carries hidden assumptions.**
- **Only the objectives of heavy standards carry over** (independence, traceability,
  evidence), not their document volume.
- **Team communication failures become context-boundary failures** between sessions,
  subagents and the builder. INFERRED.

**AI failure modes and what counters them:**
- Local fixes piling up complexity → 1, 4, 9.
- Duplication → 4, 15.
- Declaring done early → 6, 7, 16.
- Passing tests while wrong, or gaming them → 6, plus a way to flag a case as wrong.

- Inventing facts → 3, 16.

## Q3: writing instructions that are followed

**Findings** (Anthropic's prompting, skills, Claude Code and model-specific guides;
OpenAI's GPT-4.1 and GPT-5 guides; instruction-following papers):
- **Give a short reason, not long rationale.** Reasons generalise, but a loaded skill
  is a recurring token cost. VERIFIED.
- **"Do X instead" beats a bare "do not".** A prohibition works when it names the
  tempting action and the allowed substitute: "don't add features; mention them at the
  end instead". VERIFIED.
- **No capitals or MUST by default.** Recent Claude guides say to dial back aggressive
  language. If one rule is missed, emphasise that line alone, because emphasising many
  lines means none stands out. VERIFIED. Older Anthropic skill guidance still uses
  MUST, so the advice depends on the model generation.
- **Observable trigger plus action beats general advice.** "Run npm test before
  committing", not "test your changes". VERIFIED. Very prescriptive skills can degrade
  the strongest models (Fable 5), but not Sonnet or Haiku, datum's targets. VERIFIED.
- **Rules read but not applied.**
  - Context is not enforcement. Rules that must always hold go in hooks; gates go into
    checks the agent runs; verifiers with fresh context beat self-critique. VERIFIED.
  - Adherence falls as instructions grow, with a bias toward earlier ones.
    VERIFIED-secondary, on extreme instruction counts.
- **Lesson 8 is a documented failure.** Anthropic's guides describe Sonnet 5.5
  answering from training knowledge when facts may have changed. The fix: name the
  classes to check "even when you feel confident". A blanket "always search" fired on
  half of prompts that needed none (Haiku 5.5). VERIFIED.
- **Placement.**
  - A skill body is loaded once, so write standing rules, not one-time steps. VERIFIED.
  - After compaction, only the first 5,000 tokens of each invoked skill are
    re-attached, so put what must survive first. VERIFIED.
- **Length and structure.**
  - Skill bodies under 500 lines; CLAUDE.md under 200. VERIFIED, as guidance; nothing
    measures a cut-off.
  - References one level deep, with a contents list above 100 lines. VERIFIED.
  - Headings and bullets; numbered lists when order matters. VERIFIED.
  - Contradictions are resolved arbitrarily, so the stance must never disagree with a
    step. VERIFIED.
- **Examples.** Use 3–5 that are relevant and diverse so no unintended pattern is
  picked up. VERIFIED. Copying from a single example is not measured. INFERRED: give
  two or three, labelled illustrative.

**Against our 17 lessons:** the evidence agrees with 13 and says nothing about 4 (2, 3
and 17 are triggering or tooling; 11–13 count as one row). It contradicts none.
Lesson 8 agrees strongly. Lesson 9 adds an order: ask before writing the value.

**Writing guide for datum's skills** (INFERRED from the above):
1. Plain second-person imperatives; one term per concept, used the same way everywhere.
2. What holds for the whole task goes first, as standing rules.
3. Each rule is an observable trigger plus an action.
4. A one-clause reason only on rules likely to be skipped or over-applied.
5. "Do X instead" over "do not Y". Keep a prohibition only when it names the
   substitute.
6. No MUST or capitals. Emphasise one line only after a test shows it is missed.
7. Gates become checks the agent runs: end-condition lists, validate-and-fix loops,
   reviewer agents. Must-always rules go in hooks.
8. For "is X done?", spell out the procedure, not the definition.
9. Name the only exceptions and nothing else (lesson 4).
10. Say what only a technique's body holds, so its pointer line is not taken for it;
    keep any load-critical rule in the step itself.
11. Keep step skills well under 500 lines. Cut what the model already knows.
12. Headings, bullets, checklists for sequences; prose only for reasons.
13. Two or three diverse examples labelled illustrative, never one. No placeholder
    text on a live path.
14. Audit the stance and each step together for contradictions.
15. Test on Haiku and Sonnet with a Sonnet judge; change one line at a time.

## Gaps

- No source quantifies the cost of a missed flowdown.
- Brooks, Meyer, Ousterhout, Gall, ECSS, ARP4754A, the INCOSE handbook, the JATR report
  and the NTSB report were not read.
- Most evidence on AI agents is correlational and from 2024–2025.
- Nothing measured shows that any stance wording changes agent behaviour.
