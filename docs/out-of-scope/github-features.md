# GitHub features this repository does not use

**Rejected 2026-11-06 (#22).**

The idea: use more of GitHub to organise the work.

Why not: each of these repeats something the issue list, the sub-issue tree or a file
already does, or adds another place to look.

| Feature | Why not |
|---|---|
| Projects | A board repeats the issue list, and the current token cannot read it. Revisit if the sub-issue tree stops being readable |
| Assignees | One person, and agents act under the same account, so an assignee says nothing |
| Issue types | Not available on a personal account |
| Labels other than `parked` | No failure needs them, and priority is the order in `docs/handoff.md` |
| Issue forms and templates | One person writes the issues |
| Pinned issues, Discussions, wiki | Each would be another place to look |
| Automation | Nothing needs it: `Closes #N` is built in |
